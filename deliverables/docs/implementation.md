# v1 구현 범위와 검수

## 원문과 범위

기준은 저장소 루트의 `mean_concept_video_work_order.md`입니다. 원문을 수정하지 않았습니다. 이번 요청은 E0·E1이므로 E2 이후와 혼합 R 문제 출제, 전체 0/1/3/5/7/14/30일 교육과정은 구현하지 않았습니다. E0·E1의 완료 회차, 다음 복습일, 적응 속도, 추상화, 생성·계산 과제, 교실 모드를 구현했습니다.

기존 앱은 `versions/v0` 및 `v0` 태그로 보존했습니다. 원본 Git 커밋은 `216c5f3a34c1b9b448ca6e0d79133197df0e90d8`입니다. 배포 서비스 결합 정보는 새 앱에 옮기지 않았습니다. 기존 사이트를 덮어쓰지 않습니다.

## 지시서의 충돌을 해결한 방식

- E0는 공통 친구 단계를 생략합니다. E0의 방법 선택/서술 허용과 전체 객관식 금지 규칙을 함께 만족하도록 **서술 입력**을 사용합니다.
- E1의 가운데 값은 **정렬 후 가운데**라고 음성으로 명확히 합니다. 원배열의 화면상 가운데 기둥3을 가리키는 것이 아닙니다.
- 공통 봉인 연출은 같은 생성 함수·카메라·배율·시간을 사용합니다. 수량은 E0의32개, E1의24개를 보존하므로 영상 파일을 둘로 렌더합니다. 단순히 같은4×3 영상을 서로 다른 숫자 아래 재사용하지 않습니다.
- 3~5분은 기본1×에서 정상적으로 입력하는 **권장 학습 시간 예산**입니다. 생각하는 시간, 접근성 입력, 되감기, 속도 변경을 강제로 잘라5분 안에 끝내지 않습니다. 영상파일과 순수 자동 재생 시간을 학습 전체 시간으로 오인하지 않습니다.
- v1의 생성 값은 비음수 정수입니다. E0의 최대32, E1의 최대24는 전체 조건을 만족할 수 있는 값을 하나도 배제하지 않습니다. E1의0,0,0,24나 E0의8,8,8,8도 허용합니다.

## 학습과 시간 예산

| 구간 | E0 권장 초 | E1 권장 초 |
|---|---:|---:|
| 시작/방법 또는 친구 | 25 | 20 |
| 예측·확신 | 25 | 20 |
| 전개(자동 재생) | 60 | 60 |
| 비교(자동 유지) | 10 | 10 |
| 재구성 | 25 | 25 |
| 질문·발견 | 15 | 15 |
| 변주 전체 | 35 | 55 |
| 생성 | 35 | 35 |
| 고르기·봉인 | 7 | 7 |
| 합계 | 237 (3:57) | 247 (4:07) |

변주의 고르기는 각각16초, 비교는3초입니다. 입력은 잠금 해제된 직후 바로 진행할 수도 있으므로 실제 완료 시간이3분보다 짧을 수 있습니다. 반대로 더 생각하면5분을 넘을 수 있습니다. 이 앱은 강제 타이머가 아니라 상호작용 학습물입니다. 권장 입력 시간을 포함한 예산과 실제 자동 재생 시간을 문서에서 분리합니다.

처음 보는 예측에서 슬라이더를 직접 조작하고 확신도를 정해야 합니다. 슬라이더의 기존 위치가 자신의 답이면 눌러 선택하거나 Enter로 확정할 수 있습니다. 원리를 이름 붙이기 전에는 짧은 관찰 입력을 받습니다. 응답2초 미만이3번 이어지면 이유를 서술하게 합니다. 건너뛰기 벌점은 없습니다.

전개는 한 단위 블록이 목적지에 도착한 경계에서 멈춥니다. E0는 팀별 이동을 차례로 진행하므로 한 팀을 보여 주려고 다른 팀의 블록을 공중에 멈추지 않습니다. 첫 관찰의 스크러버는 이미 본 범위까지만 열리고, 재관찰은 시청한 범위 안에서 자유롭게 되감습니다. 교실 이력과 개인 이력을 분리합니다.

재구성은 매번 섞되 부분 재생 후 학습자가 만든 순서는 유지합니다. 순서가 뒤집힌 두 장면 사이만 재생합니다. 생성 확인 후 값을 잠그고 봉인 직전에도 수량을 다시 검사합니다.

## 반복과 기록

- 1회3D, 2회평면막대, 3회막대+숫자, 4회이후숫자+식.
- 4회이후에는 계산 두 문항이 붙습니다. 생성 과제는 단계에 맞는 드래그 또는 수치 슬라이더로 만들며 정해진 답 선택 방식은 쓰지 않습니다.
- 변주 새 노출 네 번마다 참 주장 한 번. 다시 듣기·되감기는 새 노출로 세지 않습니다. 원자료에 평균6이 실제 있는 참 변주도 포함합니다.
- 오차가 작고2~12초 안에 예측하면 다음 간격을 두 배, 오차가 크면 다음날0.75×로 배정합니다. 적용 결과는 시작 화면의 날짜와 다음 재생 속도에 반영됩니다. 점수나 등급은 표시하지 않습니다.
- 로그는 로컬 저장 및 JSON 내보내기. 세션 ID를 사용하여 중단 실행을 다음 실행과 섞지 않습니다.

## 기술·에셋

Three.js 0.180.0, GSAP3.13.0. [GSAP의 addPause](https://gsap.com/docs/v3/GSAP/Timeline/addPause()/)로 의미 경계를 제어합니다. Blender4.5.14 LTS에서 직접 모델을 만들고 네이티브 파일을 저장·재오픈했습니다. .blend에는 공통 모델과 E0/E1 봉인 scene이 들어 있습니다. 두 MP4는1920×1080·30fps·150프레임·5초이며 무음입니다.

블록 이동은 개체 ID를 유지하는 안내 경로입니다. 수학적 총량은 논리 모델에서 계산하며 중력에 의한 오차를 답으로 쓰지 않습니다. 친숙한 물리 형태를 사용하지만 이 버전은 강체 충돌 실험이 아니라 개념 영상입니다.

음성은 macOS `say`의 Yuna 한국어를 로컬 생성한24개 MP3입니다. 재생 시 TTS 네트워크 요청은 없습니다. 자막은 기본 꺼짐이며 설정에서 켤 수 있습니다. 사용자의 브라우저가 자동 재생을 막으면 다시 듣기 버튼으로 시작합니다.

## 확인한 것과 한계

`npm test`는 실제 GLB 파싱, 실제 Three 모델 변환, 실제 GSAP 정지 지점을 사용합니다. 렌더러와 브라우저 환경만 테스트 대역입니다. 게이트, 보존량, 유효 생성 해, 새 세션 집계, 완료 멱등성, 교실 분리, 재구성 구간, 생성 이후 잠금, 2D 전환, 독립 모듈 실행을 검사합니다. `npm run verify`는 v0의 해시, 정적 에셋, 미디어 메타데이터와 원문 지시서의 해시를 검사합니다.

Blender 모델·MP4는 실제 렌더링과 프레임 검사 및 ffprobe로 검증했습니다. 브라우저에서의 픽셀 배치, 실제 휴대폰 터치, 음성 자동재생 정책별 실기 점검은 수행하지 않았습니다. 380px 이상 반응형 스타일과 Pointer Events를 구현했으며, 실제 기기 검수는 별도입니다.
